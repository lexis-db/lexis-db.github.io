Lexis

Distributed data, in key order.

Byte-ordered partitioning built on tablets. Partitions are stored and distributed in key order, so you can query any prefix or range of a partition key and read it back in order, straight from the nodes that hold it.

scroll
01 · the idea

Partitions, stored in key order.

In Lexis the token of a partition is its key, encoded so that byte order is key order. Partitions that share a prefix are stored together, so a query on the start of a key reads one contiguous range of tablets.

02 · the token

The token is the key, byte for byte.

Each partition key component is written out as order-preserving bytes and closed with a 00 00 terminator, so memcmp on two tokens gives the same answer as comparing the keys. Text is its UTF-8 bytes. Integers, varints, decimals and timestamps get encodings that sort in CQL order, negatives included. In cqlsh and the drivers, token() is a blob.

03 · the constraint

Ordered partitioning, made for tablets.

Ordered partitioning on a single cluster-global token ring meant one set of boundaries had to suit every table. Tablets give each table its own independent mapping, so every table is balanced on its own keys.

vnodes

One ring for every table

Token boundaries are shared across the cluster. Ordered keys from different tables pile into different parts of the same ring.

tablets

A mapping per table

Each table has its own token-range-to-node-and-core mapping. There is no shared ring, so one table's distribution can't unbalance another's.
04 · hotspots

Hot tablets split and move.

The tablet load balancer splits a hot tablet and migrates the halves, down to a specific core on a specific node. A high-entropy leading key component spreads writes across the key space; whatever concentration remains is handled by splitting, with no schema changes.

05 · what you get

Partial keys become range reads.

Queries that would need secondary indexes become efficient range reads, routed to a bounded set of nodes and cores. The query model gets substantially more expressive, with no sacrifice in distribution or performance.

Prefix scans

Name the start of a partition key, get every partition under it as one contiguous range, in key order.

WHERE coll = 'collection'

Ranges on the last component

Page through a collection, or take a range of collections, with no full-cluster scatter.

AND docid > 'd100' LIMIT 2

IN, then a range

Several prefixes at once, each ending in a range: one bounded read per prefix.

colid IN ('c1','c42') AND docid > 'd1'

LIMIT means first

A LIMIT on a full scan returns the first keys of the table, in order.

SELECT * FROM docs LIMIT 2

Simpler data models

For range-ordered access patterns, secondary indexes and denormalized tables become unnecessary. One table, keyed by path.

PRIMARY KEY ((coll, colid, docid))

Routed by the drivers

The Python and Rust drivers compute Lexis tokens on the client and send each query to the node and shard that own it.

06 · prior art

Bigtable's query model on modern hardware.

Lexicographic order, per-table tablets and dynamic splitting are the model Google Bigtable has offered since 2004. Lexis brings it to a per-core, shared-nothing architecture, where a tablet split moves work to a specific core on a specific node: a finer granularity of load balancing than anything else available.

Together they make something new in open source distributed databases: Bigtable's query model on modern hardware.

Try it on one node.

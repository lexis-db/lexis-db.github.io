Motivation

Hierarchical keys are a common pattern: document stores, file and object stores, and multi-tenant data all address records by a path. For example, a document store with each document at /collection/{collectionId}/documents/{documentId}, and the whole path as the partition key.

In ScyllaDB the token is a hash of the whole path, so only a complete path can be looked up efficiently. Listing a collection, paging through it, or listing collections all name just the start of a path, and ScyllaDB rejects them:

Cannot execute this query as it might involve data filtering and thus may have unpredictable performance. If you want to execute this query despite the performance unpredictability, use ALLOW FILTERING

or, for a range on part of the path:

Only EQ and IN relation are supported on the partition key (unless you use the token() function or allow filtering)

With ALLOW FILTERING they run as full scans of every node and return rows in hash order. The usual workarounds are a secondary index, a second table keyed for each access pattern, or moving docid into a clustering column, which puts a whole collection into one partition that cannot be split.

In Lexis the token is the path itself, encoded so that byte order is path order. Documents that share a prefix are stored together, so each of these patterns becomes a read of one contiguous range of tablets, in path order, without ALLOW FILTERING.

Setup

One table, keyed by the whole document path.

Schema

Plain CQL. Every table in Lexis is ordered, so there is no partitioner option to set. Tablets are on by default for new keyspaces.

cqlsh:lexis
>CREATE KEYSPACE lexis WITH replication = {'class': 'NetworkTopologyStrategy', 'replication_factor': 1}; USE lexis; CREATE TABLE docs (coll text, colid text, docid text, body text, PRIMARY KEY ((coll, colid, docid)));
cqlsh:lexis
>INSERT INTO docs (coll, colid, docid, body) VALUES ('collection', 'c1', 'd1', 'x'); INSERT INTO docs (coll, colid, docid, body) VALUES ('collection', 'c1', 'd2', 'y'); INSERT INTO docs (coll, colid, docid, body) VALUES ('collection', 'c42', 'd100', 'a'); INSERT INTO docs (coll, colid, docid, body) VALUES ('collection', 'c42', 'd101', 'b'); INSERT INTO docs (coll, colid, docid, body) VALUES ('collection', 'c42', 'd250', 'c'); INSERT INTO docs (coll, colid, docid, body) VALUES ('users', 'u7', 'p1', 'z');

Full scan

Whatever order the rows were written in, a scan returns partitions sorted by key.

cqlsh:lexiskey order
>SELECT * FROM docs;
collcoliddocidbody
collectionc1d1x
collectionc1d2y
collectionc42d100a
collectionc42d101b
collectionc42d250c
usersu7p1z
(6 rows)

Prefix queries

Name the start of a path. Matches share a token prefix, so they are one contiguous range.

All documents in one collection

cqlsh:lexisrange read
>SELECT * FROM docs WHERE coll = 'collection' AND colid = 'c42';
collcoliddocidbody
collectionc42d100a
collectionc42d101b
collectionc42d250c
(3 rows)

Every collection under a path

Just the first component: everything below collection.

cqlsh:lexisrange read
>SELECT * FROM docs WHERE coll = 'collection';
collcoliddocidbody
collectionc1d1x
collectionc1d2y
collectionc42d100a
collectionc42d101b
collectionc42d250c
(5 rows)

Range queries

A range on the component after an equality prefix is a token range too.

A page of documents

Resume after the last document you saw.

cqlsh:lexisrange read
>SELECT * FROM docs WHERE coll = 'collection' AND colid = 'c42' AND docid > 'd100' LIMIT 2;
collcoliddocidbody
collectionc42d101b
collectionc42d250c
(2 rows)

A range of collections

Text compares byte by byte, so 'c42' >= 'c2' and c42 falls outside ['c1', 'c2').

cqlsh:lexisrange read
>SELECT * FROM docs WHERE coll = 'collection' AND colid >= 'c1' AND colid < 'c2';
collcoliddocidbody
collectionc1d1x
collectionc1d2y
(2 rows)

IN queries

IN on a component gives one range per value.

Several collections at once

cqlsh:lexis2 ranges
>SELECT * FROM docs WHERE coll = 'collection' AND colid IN ('c1', 'c42');
collcoliddocidbody
collectionc1d1x
collectionc1d2y
collectionc42d100a
collectionc42d101b
collectionc42d250c
(5 rows)

Several collections at once, from a given document on

Each path in the IN list can end in a range.

okcollection / c42 / *all documents in c42
okcollection / c42 / d100..d200a range at the end
okcollection / {c1, c42} / d100..*two paths, each ending in a range
not okcollection / * / d100a gap in the middle, so the matches are not next to each other
cqlsh:lexis2 ranges
>SELECT * FROM docs WHERE coll = 'collection' AND colid IN ('c1', 'c42') AND docid > 'd1';
collcoliddocidbody
collectionc1d2y
collectionc42d100a
collectionc42d101b
collectionc42d250c
(4 rows)

d1 is excluded, and since 'd100' > 'd1' in text order, all of c42 is included.

Ordering

Key order is the storage order, for every key type that has one.

The first rows of the whole table, in key order

LIMIT on a full scan returns the first keys of the table.

cqlsh:lexiskey order
>SELECT * FROM docs LIMIT 2;
collcoliddocidbody
collectionc1d1x
collectionc1d2y
(2 rows)

Numeric keys

int, bigint, varint, decimal and timestamp keys sort in CQL order, negatives included, and ranges on them are token ranges.

schema
CREATE TABLE readings (sensor int PRIMARY KEY, v int);
-- insert sensors -70000, -1, 0, 1, 70000 in any order
cqlsh:lexisrange read
>SELECT sensor FROM readings WHERE sensor > -1;
sensor
0
1
70000
(3 rows)

Tokens

The token is the key, so you can read it.

token() is a blob

token() returns the encoded key: each component's bytes, then 00 00. Here that is collection, c42, d100.

cqlsh:lexis
>SELECT coll, colid, docid, token(coll, colid, docid) FROM docs WHERE coll = 'collection' AND colid = 'c42' AND docid = 'd100';
collcoliddocidsystem.token(coll, colid, docid)
collectionc42d1000x636f6c6c656374696f6e00006334320000643130300000
(1 row)

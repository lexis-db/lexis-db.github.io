Get Lexis running

Get a node running, connect the clients that speak Lexis tokens, and start querying in key order. Lexis 1.0 is a fork of ScyllaDB 6.2, so for configuration and operations, the ScyllaDB 6.2 documentation applies.

Run Lexis

A single node in one command, or a cluster with Compose.

Quick start

One node, one command.

terminal
docker run --name lexisdb -d 0x6a6f6e6e79/lexisdb
docker run --name lexisdb -d 0x6a6f6e6e79/lexisdb

With cqlsh alongside it, on a shared Docker network:

terminal
docker network create lexis
docker run --name lexisdb --network lexis -d 0x6a6f6e6e79/lexisdb

# once the node is up
docker run -it --rm --network lexis 0x6a6f6e6e79/lexis-cqlsh lexisdb
docker network create lexis docker run --name lexisdb --network lexis -d 0x6a6f6e6e79/lexisdb # once the node is up docker run -it --rm --network lexis 0x6a6f6e6e79/lexis-cqlsh lexisdb

Then try the examples.

Clients

cqlsh, drivers and tools that speak Lexis tokens. The drivers compute tokens on the client, so each query goes straight to the node and shard that own its partition, following Lexis tablet routing.

cqlsh

token() values print as hex blobs. COPY TO and COPY FROM split work by Lexis token ranges, and BEGINTOKEN, ENDTOKEN and SHOW REPLICAS take hex tokens. Installing it also installs the Lexis Python driver.

pip
pip install git+https://github.com/jk89/lexis-cqlsh
cqlsh <host>
pip install git+https://github.com/jk89/lexis-cqlsh cqlsh <host>
docker
docker run -it --rm 0x6a6f6e6e79/lexis-cqlsh <host>
docker run -it --rm 0x6a6f6e6e79/lexis-cqlsh <host>

Python

The package is lexis-driver, imported as cassandra like upstream, so remove other drivers first. token() values come back as bytes.

pip
pip uninstall scylla-driver cassandra-driver
pip install git+https://github.com/jk89/lexis-python-driver
pip uninstall scylla-driver cassandra-driver pip install git+https://github.com/jk89/lexis-python-driver
app.py
from cassandra.cluster import Cluster

session = Cluster(['127.0.0.1']).connect('lexis')

# All of user u42's orders, in key order.
rows = session.execute(
    "SELECT order_id, item FROM user_orders WHERE user_id = %s",
    ('u42',),
)
for row in rows:
    print(row.order_id, row.item)

Rust

A drop-in for the scylla crate. token() values are read as Vec<u8>.

Cargo.toml
[dependencies]
scylla = { git = "https://github.com/jk89/lexis-rust-driver" }
[dependencies] scylla = { git = "https://github.com/jk89/lexis-rust-driver" }
main.rs
use scylla::client::session_builder::SessionBuilder;

let session = SessionBuilder::new()
    .known_node("127.0.0.1:9042")
    .use_keyspace("lexis", false)
    .build()
    .await?;

// Every order of every user after u1, in key order.
let rows = session
    .query_unpaged("SELECT user_id, order_id FROM user_orders WHERE user_id > ?", ("u1",))
    .await?
    .into_rows_result()?;
for row in rows.rows::<(String, String)>()? {
    let (user_id, order_id) = row?;
    println!("{user_id}/{order_id}");
}

Tools

lexis-tools-java reads and writes Lexis sstables (sstabledump, sstablemetadata, sstableloader), and nodetool works against a Lexis node through lexis-jmx. Tokens are shown and accepted as hex.

terminal
nodetool status
nodetool repair -st <hex token> -et <hex token> lexis user_orders
nodetool status nodetool repair -st <hex token> -et <hex token> lexis user_orders

Toolchain

Lexis builds inside a toolchain container, so the only thing you need on the host is Docker. The first build takes a while; after that, builds are incremental. Full details are in guide-build-and-test.md.

terminal

cd lexisdb
docker pull docker.io/scylladb/scylla-toolchain:fedora-40-20240710

Reference

What Lexis adds, and where to read about everything else.

What's new

Ordered partitioner

Every table is partitioned by an order-preserving encoding of its key, on tablets. Full scans return partitions in key order.

Partition order

PARTITION ORDER BY declares each partition key column ASC or DESC, as CLUSTERING ORDER BY does for clustering columns.

Partial key queries

A prefix of the partition key, a range on its next column, or an IN followed by a range are served as range reads.

Blob tokens

token() returns the encoded key as a blob. cqlsh and the tools show tokens as hex.

Typed key ordering

Every scalar key type sorts and ranges as CQL compares it; text and blobs sort lexicographically.

Token-aware clients

Python, Rust, cqlsh, nodetool and sstable tools all understand Lexis tokens.
